# Live tracking

Version 0.2 adds VS Code activity estimates and Claude Code hooks to the original local collector.

## Editor signals

The extension listens to explicit keyboard and mouse selection changes in an active editor belonging to the connected workspace. It excludes command-driven and undefined selection changes. It does not subscribe to file edits as a reason to start time.

The distinction comes from the [VS Code selection-change API](https://code.visualstudio.com/api/references/vscode-api#TextEditorSelectionChangeKind): document changes and commands can be generated by extensions or automation. Even keyboard/mouse signals are observations, not proof of identity or honest work.

An activity clock clips intervals at a two-minute idle boundary. Window blur closes the current interval and clears activity. A scheduling gap over 30 seconds or a backwards clock jump resets the window. A later signal starts a fresh interval without filling the gap.

Every 15 seconds, the adapter sends immutable samples with a random ID, project ID, start/end timestamps, and signal type. It sends no text, file path, code, or keystrokes.

## Storage and replay

SQLite stores original samples and counted slices separately. In a transaction, the collector validates each sample, removes overlaps with already counted slices across all projects, subtracts recorded pause intervals, and saves the remaining pieces.

Identical IDs are safe to replay. Conflicting IDs roll back the batch. Samples over 30 seconds, older than seven days, or more than five seconds in the future are rejected. The small future tolerance accommodates minor clock skew, not extended offline clock drift.

Overlapping time belongs to the first accepted sample. This is deterministic for a given arrival order and avoids counting multiple editor windows twice. It is not a judgment about which project deserves credit.

The VS Code queue lives in workspace storage. It retains up to 5,000 samples and retries in batches of 500. Deleted projects disconnect the adapter and discard that project's pending samples.

## Claude hooks

The adapter uses the [documented Claude hook lifecycle](https://code.claude.com/docs/en/hooks): UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, Stop, StopFailure, and SessionEnd.

The installer updates project-local settings while retaining unrelated settings and hook groups. Reinstalling replaces the matching HackTrail entries instead of duplicating them. A settings backup is retained locally.

The hook process extracts only allowed event metadata. It writes a queue entry before attempting delivery, reuses event IDs on retry, and exits without blocking Claude when the collector is unavailable. Queues retry on a subsequent hook; there is no separate background retry daemon.

Agent elapsed time comes from matching start and finish records within the review period. Overlapping completed runs are merged for the total. Unmatched starts and runs over 12 hours are excluded and flagged. A session that crosses the selected review boundary may not have both endpoints in the report. Agent duration can include permission waits and other waiting.

## Review and export

The dashboard uses the browser's local calendar boundaries for its seven-day request. Counted time slices are clipped to the requested range, including at midnight.

Review summaries are deterministic counts and notes, not an LLM assessment. They show tool errors and incomplete agent runs alongside the estimated editor time. The full project export contains events, original time samples, counted slices, and the estimation policy.

## Validation

Tests cover idle expiry, focus loss, sleep and clock gaps, offline replay, overlapping projects, pause/resume, conflicting IDs, deleted projects, and privacy boundaries. Adapter tests exercise the VS Code extension against a stub editor API and the real time store.

Browser checks cover import/export, live updates, notes, pause controls, review, desktop/mobile layouts, and VSIX download. The Claude integration check installs hooks into a temporary workspace, executes the actual bundled hook process, tests offline retry, and verifies that unrelated settings survive removal.

These checks do not replace a real VS Code host test, a Windows laptop test, or comparison against consented reference work sessions.
